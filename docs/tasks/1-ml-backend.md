# №1: ML + Backend

**Твої файли:** `pipeline/`, `backend/`, `requirements.txt`
**Не чіпай:** `frontend/`, `shared/mapping.json` (просто повідом №4, якщо додаєш фічу)

## Контекст
Pipeline бере кадри з відео (5 на секунду), рахує фічі 0..1 і пише `data/features/<id>.json`. Backend (FastAPI) віддає їх фронтенду. Звук синтезується в браузері, не на сервері.

## Задачі (за пріоритетом)

### MVP (до 12-ї години)
1. **Перевірити pipeline на справжніх відео** від №3. Подивитися, чи фічі «живі», тобто не всі ≈ 0 або ≈ 1. За потреби підправити нормалізацію в `pipeline/features.py`.
2. **Підтримати `crop` з `data/catalog.json`.** Якщо у відео є поле `"crop": [x, y, w, h]`, `pipeline.run` бере його автоматично (тоді `--crop` вручну не потрібен).
3. **Скрипт `pipeline/run_all.py`:** проходить по всіх відео з `catalog.json`, у яких є `data/raw/<id>.mp4`, і рахує фічі.
4. **Backend: підмішати описи.** `/api/videos` додає до кожного відео поля з `data/descriptions.json` (його заповнює №5; якщо файлу немає, не падати).

### Покращення (12–30 год)
5. **Фіча `scene_cut`** (0/1): різка зміна кадру (титри, перехід). №4 може робити на ній акцент.
6. **Домінантні кольори:** k-means на 3 кольори, які стають новими фічами `hue_1`, `hue_2`… або `dominant_hue`.
7. **ML (опційно):** CLIP zero-shot, фіча `mood_calm` / `mood_intense` (0..1) за промптами «a calm peaceful scene» / «an intense stormy scene». Рахувати 1 раз на секунду, далі інтерполювати.
8. **Колірна шкала → реальне значення** (найсильніше для журі): для 1 відео (наприклад, CO₂ або температура) зчитати колірну шкалу з легенди і перевести колір пікселя в реальну величину.

### Фінал
9. Документувати фічі у `pipeline/features.py` (одна строка на фічу: що вона означає). Це потрібно №5 для тексту подачі.

## Готово, коли
- `python -m pipeline.run_all` рахує фічі для всіх завантажених відео
- `/api/videos` повертає описи, `/api/features/<id>` повертає реальні дані
- нова фіча додана в `FEATURE_NAMES` і про неї знає №4
