# №5: Контент, доступність, презентація

**Твої файли:** `data/descriptions.json`, `docs/submission/` (усе для подачі)
**Можеш пропонувати** тексти для UI: передавай №2

## Контекст
Челендж про **доступність**: наукові візуалізації NASA недоступні незрячим людям, і звук має це змінити. Журі оцінює не лише код, а й історію, зрозумілість і вплив. Це твоя зона.

Опис челенджу: https://www.spaceappschallenge.org/2026/challenges/the-earth-information-jukebox/

## Задачі

### Перші 12 годин
1. **Описи відео** у `data/descriptions.json` (формат нижче) для кожного відео з `data/catalog.json`:
   - `short`: 1 речення, що показує візуалізація;
   - `science`: 3–5 речень, яке явище, чому це важливо, що змінюється;
   - `audio_description`: опис для незрячих (що відбувається на екрані по ходу відео);
   - `how_it_sounds`: як дані перетворено на звук (бери з пояснень №4).
   ```json
   {
     "night_lights": {
       "short": "...",
       "science": "...",
       "audio_description": "...",
       "how_it_sounds": "..."
     }
   }
   ```
   Джерело: сторінки `svs_page` NASA. Пиши англійською (подача англійською), українська за бажанням.
2. **Дослідження:** знайди 2–3 приклади сонифікації (NASA, інші) та 1–2 факти про доступність науки для незрячих. Вони знадобляться в презентації.

### 12–30 год
3. **Тестування доступності** разом із №2: пройди сайт **лише клавіатурою** і з **VoiceOver** (Cmd+F5 на Mac) із закритими очима. Запиши, де незручно.
4. **Чернетка тексту подачі** в `docs/submission/project.md`: назва, проблема, рішення, як працює, використані дані NASA, що далі. Space Apps просить короткий опис і посилання на демо.

### 30–48 год
5. **Демо-відео ≤ 30 с** (сценарій + запис екрана зі звуком): проблема → натискаємо Play → чути, як змінюється звук → навіщо це.
6. **Слайди/картинка** для подачі, якщо потрібно.
7. **Фінальна подача** на сайті Space Apps разом із капітаном. Перевір, що репозиторій публічний і посилання працюють.
